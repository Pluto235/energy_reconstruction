为什么需要 Stage C

Crab SED v1 流水线前两步都在 MC 侧：Stage A 计算二维探测器响应 eta_b(E_true, theta) 和有效面积，Stage B 在 Crab 赤纬带上给每个 v1 cell 计算 PSF 与积分半径。要把这些 MC 结果用于真实观测，必须先把观测数据整理成同样的观测空间单元 b = (Nhit bin, log10 E_pred bin)，并且给每个事件补上时间和天球坐标。

这正是 Stage C 的职责：它不是做源显著性，也不是做背景模型，而是把观测 eval ROOT 变成一个干净、列式、可复查的数据集。后面的 Stage D 会用这份数据重建直接积分法接收度和 rate 曲线；Stage E 会在每个 cell 的 on-region 内计数并和背景预测组合。

和 quicklook 天图的区别

此前的 apply/plot_crab_cell_skymaps.py 已经处理过同一批 1258 个观测文件，并画了 Crab 附近的 cell 天图。这一步很有价值，但它只是 Stage C/D/E 之间的诊断 quicklook：它只看 Crab 附近 ROI，少了正式路线要求的 dcedge > 20 m，也没有输出月度 parquet 或 manifest。

当前 Stage C 则是正式数据规约：使用全天清洗后的 v1-cell 事件，不做 Crab ROI 过滤；输出 parquet 分区目录、manifest、metadata、source file 表、cutflow 和 cell counts。它为直接积分法背景保留了必要的时间、天球坐标和局部方向诊断列。

输入、对齐与正式 Cuts

  • 观测 eval ROOT：/mnt/mydisk/WCDA_observation_eval/<MMDD>/Esg*.root，读取 t_eventout。
  • 时间恢复 friend tree：/mnt/mydisk/WCDA_observation_eval/recovered_time/<MMDD>/*.time.root，读取 t_recovered_time。
  • 对齐方式：同名 eval ROOT 与 .time.root 按 entry 顺序对齐；正式 full run 默认 missing time 或 entry mismatch 即失败。
  • 正式 cuts：match_status == 0、pincness < 1.1、fitstat == 0、theta < 50 deg、dcedge > 20 m。
  • cell selection：用 nv 和 ml_logE_pred 映射到 apply/config/cell_selection_v1.csv 的 18 个 v1 physical-band cells；不在表内的事件丢弃。

输出数据集

Stage C 输出采用 Hive-style parquet 分区目录，月份来自文件名 EsgYYYYMMDD_HH.root 的 YYYYMM，而不是逐事件 MJD 重新拆分。这样每个输入 ROOT 对应一个 parquet part 文件，便于 Slurm 并行写入、失败定位和后续扫描。

  • apply/output/stage_c/current/obs_events/yyyymm=YYYYMM/part-*.parquet：正式观测事件数据集。
  • apply/output/stage_c/current/obs_events_manifest.json：dataset path、schema、partition 和 parquet 文件列表。
  • apply/output/stage_c/current/obs_events_metadata.json：输入路径、cuts、cell selection、处理参数、MJD coverage、rough live-time basis 和 promotion 状态。
  • apply/output/stage_c/current/source_files.csv：每个输入文件的 entry 数、输出 part、MJD span 和粗略 live-time 基础量。
  • apply/output/stage_c/current/obs_events_cutflow.csv：global/month/file cutflow。
  • apply/output/stage_c/current/obs_events_cell_counts.csv：global/month/file 的 18-cell 事件数。
  • apply/output/stage_c/current/obs_events_summary.md：机器输出之外的简短摘要。

下一步

Stage C 完成后，后续工作可以转向 Stage D：直接积分法背景估计。Stage D 应读取 apply/output/stage_c/current/obs_events/，按 cell_id 分组构建局部接收度图和 rate 曲线，并用 Stage B 的 r_opt 支持 Stage E 的 Crab on-region 计数。

本报告中的 quicklook 对照只用于解释为什么需要正式 Stage C；最终背景、excess 和 Li-Ma 显著性不应从 quicklook sideband 图读取，而应来自 Stage D/E 的正式输出。
